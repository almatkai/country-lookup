## Configuration and surfaces

`extension.json` preserves the own manifest's exact required preferences, casing, descriptions and dropdown labels: password **apiKey / API Key**, and **entriesWithoutIsoCode / Show Countries**, values `show`/`hide`. No default dropdown value is invented. An empty key or missing/invalid selection produces an actionable configuration error before a request. Known placeholder/synthetic credentials are blocked at the product endpoint. QA never reads profile secrets, asks for a real key, or calls that endpoint.

The sole own manifest command is **index / Search Countries**. Own `src/tools` contains three helper modules but declares no `tools`/AI surface in its manifest. Upstream Raycast declares those tools; the private SDK has no equivalent AI tool-registration runtime. They are **not** implemented or registered as commands here. V1 README statements about Quick AI do not establish native tool support.

## Requests, cache and failure behavior

The implementation follows the **locked executable `@yusifaliyevpro/countries@5.2.1`**, not old REST Countries v3 documentation. It sends GET to `https://api.restcountries.com/countries/v5?limit=100&offset=N`, with `Authorization: Bearer <trimmed preference>`, no body, search query, response-field projection, filter or alternate endpoint. As in own source, offsets **0, 100, 200** start together; out-of-range pages are ignored according to page-zero `meta.total`. Offsets 300+ follow sequentially when required. Results come from `data.objects`/`data.meta`; `_match` and `_meta` are removed, other fields and API order remain. Missing meta follows the client's first-page length fallback. Requests are not made per local search character or on load-more/view refresh.

Success is cached four hours in this extension's private `country-lookup-cache/storage.json`, with an in-process cache of the same data. The record is fingerprinted with SHA256 of private profile directory plus key (separated), so another key/profile cannot reuse it. The key and preference snapshots are never persisted, exposed in views, error text, logs, raw country JSON, package metadata or fixtures. Keys are bounded to 4 KiB ASCII credentials; copy content is bounded to 1 MiB. A response reflecting the credential as text/key is rejected. Only public synthetic values appear in mock authentication tests. A successful persisted cache survives process restart. Expiration is checked against its acquisition time; malformed private state is an actionable error.

Refresh clears **only this client's cache**, explicitly revalidates, and drops old visible data after failure, matching the actual `usePromise` failure path. The source's misleading success-toast-after-failure behavior is intentionally corrected. The header also carries the failure so the baseline renderer cannot hide it behind its generic empty-search message. Failure remains visible with **Retry**. Ordinary search, heartbeat/refresh-session, queued/canceled work and restart never silently retry a failed fetch. A deliberate open may use a valid cache; a deliberate Retry/Refresh may spend quota.

Native finite bounds are explicit: 100 records/page, 2,000 records/20 pages, 8 MiB/page, 24 MiB accepted aggregate payload, 45-second complete fetch deadline, 5-second connect/15-second request deadlines, 48 JSON levels, 500,000 JSON nodes/page, 64 KiB/string, 1 KiB/key, 256 entries/detail array. One subsequently rejected page may be read before the aggregate limit is detected (at most another 8 MiB). Redirects, automatic HTTP retries, proxies and HTTP product endpoints are disabled. Inconsistent counts/offsets/continuation, short in-bounds pages and repeated page bodies fail visibly; no partial list is called “all countries.” Remote error bodies/status text/headers are never forwarded; actionable fixed messages replace potentially secret-bearing server errors.

## Visible behavior and finite parity

`hide` filters solely by truthy **ECMAScript-trimmed** `codes.alpha_3`; there are no classification, recognition, disputed-status or political predicates. `show` retains everything. A genuine source test distinguishes BOM (trimmed) from NEL (retained), where Rust's ordinary trim would be wrong. `namesByCode` is built **after filtering**, from trimmed alpha-3 to source common-name fallback, with last-write Map semantics. Borders use an exact map lookup or the original, untrimmed border code.

The renderer baseline supports real split **List.Item.Detail**. Every row uses a validated remote flag or **Globe**, source common-name fallback, and all source keywords: official/alternate names, codes, region/subregion, demonym, continents, capitals, languages, currencies and TLDs. Official subtitle and region/population accessories appear only when detail is hidden. Native search is finite case-insensitive **substring matching**, including those keywords; it does not claim Raycast fuzzy-search parity. `__hasServerSearch` makes the host use those local Rust results rather than its title/subtitle-only filter. All records are loaded once; load-more does not spend quota. A view exceeding 8 MiB asks for a narrower local search rather than emitting an oversized protocol frame.

Detail metadata preserves the source order and optional separators: official/native names, ISO/numeric/IOC/FIFA codes; capital, region, continent, population, rounded area, landlocked, demonym, units, government; languages/currencies, calling code, week/academic/fiscal dates, driving side/signs, number format, TLDs, timezones, borders, memberships; optional official/Wikipedia/Google Maps links. Flags/descriptions/headings are included. Hiding details removes the native detail node because this host keys layout on node presence, rather than `isShowingDetail` alone.

Actions preserve ordinary row order: **Toggle Details**, conditional Google Maps/OpenStreetMap/Wikipedia, **Copy as Text**, **Copy Country Name**, optional **Copy Country Code / Copy Flag Emoji**, **Copy Raw JSON**, **Refresh**. Text includes every source label, separator, optional field, region/unit punctuation and source helper behavior. Tests execute own full helpers/components to obtain expected output; expectations are not generated by Rust. `Intl.NumberFormat('en-US')` grouping/default three-digit fraction rounding, Math.round area, missing versus null, false/zero/empty values and membership ordering are covered by a finite 21-case oracle, not a claim of implementing arbitrary JavaScript coercion.

Raw JSON follows `JSON.stringify(country, null, 2)` within the accepted finite JSON domain: preserve insertion order, enumerate integer-like keys first, normalize parsed numbers to JS IEEE754 and emit them with ryu-js, including signed zero, large/fractional/exponent values. Unknown fields survive. The oracle includes integer-like and non-index keys, precision beyond 2^53, subnormal/max finite values, controls, Unicode and paired escaped surrogates. Nonfinite numeric overflow, excessive structure and unpaired escaped surrogates are rejected visibly; protocol framing also requires valid UTF-8/JSON and LF. There is no claim of arbitrary ECMAScript object/getter/prototype/undefined or all malformed API-schema coercion parity. Invalid known top-level object/array and primary text shapes fail instead of guessing.

`showing-detail` defaults true and persists under the exact source key. `src/store.rs` implements a **bounded adaptation of the pinned SDK's storage semantics using SDK-granted private paths**, because the pinned convenience helpers use unbounded `fs::read`. It serializes transactions across sessions, rejects corrupt/non-object/oversized or symlinked storage, validates the boolean on every event, preserves unknown keys, writes a synced same-directory tempfile atomically, and uses private Unix permissions. Toggle state is at most 64 KiB; country cache at most 32 MiB. No V1/profile migration is invented. Cross-process simultaneous writers are outside the host contract (one process per extension/profile); the host owns private path isolation. External hostile replacement of an ancestor directory is not an OS sandbox guarantee.

## Safety and lifecycle

Only `clipboard.write` and `shell.open` are granted. Calls are typed **host.clipboard.write `{text}`** and **host.shell.open `{target}`**. No settings/AI/core bridge is invented. The exact optional settings contract exists in this baseline but is unnecessary; configuration guidance uses normal preferences. Strict acknowledgements accept only `{ok:true}` and an optional string `message`; null, booleans, `ok:false`, conflicting error/success fields or unexpected fields are failures.

Copy/Open intent is consumed before awaiting the host, held privately with exact prepared bytes/URL, and retried only through an explicit **Retry Previous Action (May Repeat)** (maximum three total attempts). Retry does not fetch or reformat, and is exposed in current row action menus. An uncertain/canceled host effect is not claimed successful. Unknown error strings are not reflected. Search text and fetch/effect revision tokens are committed through SDK-staged Value state; discarded search state is restored from the last committed snapshot. Session-owner and epoch action IDs reject stale/cross-session requests. In-flight/canceled fetches become an explicit Retry state. Storage/HTTP/OS effects are not rolled back by cancellation. A session-scope SDK-owned drop guard removes authoritative registrations even when a failed/canceled open never gets dispose. There are no adapter-owned detached tasks, polling loops, leases or producer threads; static views set `refreshMs:null`.

All remote names/descriptions are escaped as literal Markdown text, not interpreted as links/buttons/HTML. Official/map/Wikipedia actions and metadata links accept independently validated public http(s) URLs: no credentials, control/encoded-control strings, shell/file/custom schemes, loopback/numeric/local/special-use domains or nonstandard ports. Validation does not DNS-pin public domains. Flag images accept HTTPS PNGs only from **flagcdn.com, api.restcountries.com, restcountries.com**, without credentials, query/fragment or port; other shapes fall back to Globe. No API credential is forwarded to an image host. The locked library exposes `flag.url_png` but does not constrain hosts, and no authenticated live response was sampled: this is a deliberate finite origin policy, not an assertion that all live flags use those origins. The source's `?raycast-width=320` suffix is omitted, since this renderer does not implement it and it can corrupt URLs. Host CSP is null at the inspected baseline; validation happens in this extension. Image redirects, decoding, availability and size remain browser/host concerns. Actual GUI, theme/icon fidelity, all OS shortcuts, remote image success and live-data acceptance remain unverified. The host uses its own action menu/keyboard behavior and glyph set; shortcut/theme parity is not claimed.

## Host prerequisites — review only

`integration/` contains generic patches, **never applied to host**:

- `registry-active-resources-and-exact-alias.patch`: use the verified active version's resource root for extension/command icons, while keeping preferences at the canonical root; resolve only exact declared trusted replacement IDs, including own `com.tezbar.country-lookup`. The baseline handles the Raycast slug alias but misses this own alias. Native canonical routing does not require the alias patch; correct offline launcher icon discovery does require the resource-root fix.
- `detail-primary-click.patch`: avoid passing React MouseEvent as an action ID. This genuine baseline bug is reproduced and fixed in an isolated renderer seam. The current command uses List split detail, so this standalone Detail-button bug is not on its ordinary path.

Controlled List dropdown selection and accessory tooltip gaps were rechecked in actual source. This command has no List dropdown or tooltip contribution, so no workaround/extra control is invented. Required preferences still use their manifest dropdown. `scripts/host-seams.py` and `tests/host_seams.rs` compile actual extracted registry/validator functions before/after with explicit synthetic collection/platform dependencies; launcher descriptors are deliberately absent. These are seam tests, **not a full host build or install test**. Full exact baseline files/hashes are under `provenance/`.
